# Воспроизведение и обновление

Команды выполняются из папки courses/olympiad-math-10 репозитория teaching. Скрипты используют только стандартную библиотеку Python и уже установленный lxml. Для файлов нужны Poppler и 7z; для документов - Pandoc и LibreOffice. Установка через pip не используется.

## Локальная сборка

Git-клон с установленным Git LFS автоматически скачивает оригиналы и планы. Команда python scripts/restore_materials.py сверяет эти файлы и извлекает текст без сетевой загрузки. Если в рабочей папке остались указатели, выполнить git lfs pull. Для пересборки планов исходные страницы публикаций не нужны. Команды выполнять из папки курса по порядку:

```sh
python scripts/annotate.py
python scripts/build_catalog.py
python scripts/make_course.py
python scripts/publish.py
```

Скрипт build_archive создаёт реестр и извлекает текст, не изменяя оригиналы. build_catalog выделяет номера 10 класса и связывает публикации. annotate собирает исследовательские файлы annotations-*.txt, сортируя их по имени; поздний файл с тем же идентификатором уточняет разметку. make_course содержит исходную годовую программу из 34 тем. publish создаёт отчёты, CSV, данные локального каталога и рабочую последовательность с октября.

build_operational_plan.py читает data/operational-plan.json, общий банк тем и задач и проверенные даты из data/calendar.json. Он проверяет доступные субботы и запрещает назначать подготовку к опубликованному этапу на дату этого этапа или позже. Фактическое проведение пары отдельно отмечается в данных; предполагаемая суббота не означает проведённого занятия. Сайты организаторов скрипт не проверяет автоматически.

Для отдельной пересборки рабочего календаря выполнить python scripts/build_operational_plan.py. Для печатного листка конкретного занятия выполнить python scripts/build_session_handout.py 2026-10-03: источник course/sessions/2026-10-03/student.md, результаты student.docx и student.pdf через системные Pandoc и LibreOffice. teacher.md хранит сценарий и решения отдельно от ученического листка. Эти бинарные результаты отслеживаются через Git LFS.

Ручные исследовательские записи хранятся в research/annotations-*.txt и не генерируются по ключевым словам. Ключи решения записаны после сверки с опубликованным решением. Остальные метки приемов у прочитанных условий являются педагогическими кандидатами.

После сборки экспортировать оба согласованных документа и проверить результат:

```sh
python scripts/export_documents.py
python scripts/check_plans.py
python scripts/validate.py
node scripts/check_catalog.js
```

План для сдачи собирается непосредственно из data/lessons.json и data/program.json. Его оформление реализовано в scripts/docx_layout.py и повторяет структуру исходного образца: сводная таблица разделов и часов без КТП. Подробные занятия и задачи находятся в рабочем плане. Для изменения только оформления программы для сдачи используется export_documents.py --submission-only; рабочие DOCX/PDF при этом не пересобираются. Для рабочего Word используется стиль собранного документа для сдачи; отдельный бинарный шаблон не нужен. PDF создаётся LibreOffice.

Проверка без готовых документов: python scripts/check_plans.py --source-only. Для проверки собранного официального DOCX без рабочего Word и PDF: python scripts/check_plans.py --submission-only. GitHub Actions скачивает только четыре плана, собирает официальный DOCX во временную папку через build_submission.py --output и сравнивает его с сохраненным через check_plans.py --rebuilt-submission. Временные метки создания не учитываются, остальное содержимое пакета должно совпадать.

## Загрузка новых источников

data/candidates.json содержит отобранные публикации и их предметные метаданные. data/pages.json содержит статус и происхождение фактических загрузок. collect.py не скачивает повторно адрес со статусом ok; --force нужен только при сознательной повторной проверке.

```sh
python scripts/collect.py --url-file data/expanded-urls.txt --workers 6
```

discover.py извлекает ссылки из уже сохранённых официальных индексов и архивных страниц. Его выполнение заново формирует список кандидатов, поэтому прежде сохранить ручные добавления, если они появились. Новый сезон, класс и роль файла нужно проверить по самой публикации до включения в учебный банк. После загрузки исходных публикаций python scripts/build_archive.py заново создаёт оригиналы и реестр. В обычном Git-клоне архив уже получен через LFS, а этот этап не выполняется до загрузки новых источников. Для явного восстановления опубликованного снимка используется restore_materials.py --release; снимок может отставать от main.

У коллектора есть ограничение размера файла 35 MiB и тайм-аут. Не загруженные кандидаты не объявляются документами. Для tasks.olimpiada.ru используется публичный HTTP-адрес того же файла; остальные HTTPS-проверки не отключаются. При недоступности сети конкретного окружения загрузку следует запускать в разрешённом сетевом режиме, без отключения проверки сертификатов.

## Что проверять после обновления

validate.py проверяет сигнатуры и SHA256 всех документов, ссылки карточек, границы страниц, полный состав регионального ядра и МОШ, 34 занятия, часы, наличие сверенных решений у основных тематических задач и отсутствие преждевременной выдачи контрольного резерва. Недоступные исторические ссылки и проблемы муниципального текстового слоя остаются в отдельных журналах.

Календарная справка research/calendar.md и data/calendar.json обновляются после чтения новых первичных источников. Скрипты не угадывают сроки следующего сезона. Оформление хранится в исходном коде; оба Word-документа и PDF являются результатами сборки.
