# Хранение материалов и история изменений

В Git сохраняются исходные данные, тексты, исследовательская разметка, локальный каталог и скрипты. Оригинальные олимпиады и готовые DOCX/PDF публикуются во вложениях GitHub Releases. Их версии не попадают в .git.

Обычный Git допускает бинарные файлы. Неизменённый PDF не копируется при каждом коммите. Рост связан с новыми версиями файлов; внутри PDF и DOCX небольшая видимая правка может менять значительную часть сжатых данных. В этой коллекции оригиналы занимают около 160 MiB и обычно не меняются, а документы курса пересобираются чаще.

Постоянный commit --amend не используется: он создаёт новый коммит, старый остаётся в reflog до очистки. Публикация такого изменения требует force push и усложняет работу с другими копиями. Git LFS хранит бинарные объекты отдельно, но тоже сохраняет версии и имеет квоты на хранение и скачивание. Для готовых образовательных материалов подходят Releases с обычной историей исходников.

## Получение материалов

```sh
python scripts/restore_materials.py
python scripts/export_documents.py
python scripts/check_plans.py
```

restore_materials читает data/release.json, скачивает зафиксированный архив текущей версии, сверяет SHA256 и восстанавливает archive/. Перед записью проверяются пути внутри ZIP. Уже имеющийся совпадающий файл не перезаписывается; несовпадающий файл не заменяется без явно указанного --replace. Затем извлекается текст для локальной проверки и поиска.

Полный offline ZIP можно использовать без Git: после распаковки открыть index.html. Он содержит также оригиналы, оба плана и методические материалы.

## Синхронизация планов

Единый источник учебных занятий - data/lessons.json, который строится scripts/make_course.py. Автор, учебный год и описания разделов хранятся в data/program.json. План для сдачи и рабочий план используют одинаковые темы, порядок, цели и часы. Дополнительные рабочие поля содержат номера задач и методические пояснения.

```sh
python scripts/make_course.py
python scripts/publish.py
python scripts/export_documents.py
python scripts/check_plans.py
python scripts/validate.py
node scripts/check_catalog.js
```

DOCX и PDF являются результатом сборки. После ручной правки готового документа её нужно перенести в исходные данные, иначе следующая сборка её заменит. Проверка сверяет оба документа и Markdown с исходным планом; GitHub Actions также проверяет согласованность текстов и собираемого плана для сдачи.

## Публикация новой версии

Использовать новый тег для содержательного обновления. Сначала завершить проверку документов, выбрать тег, затем подготовить вложения и контрольные суммы:

```sh
python scripts/package_release.py --tag 2026.10.01
git add .
git commit -m "feat(course): update curriculum and materials"
git push
gh release create 2026.10.01 --repo partanskiy/olympiad-math --target main --title "Олимпиадная математика 10 класса, 2026/2027" --notes-file dist/release-notes.md dist/olympiad-math-materials.zip dist/olympiad-math-offline.zip dist/submission-plan.docx dist/submission-plan.pdf dist/working-plan.docx dist/working-plan.pdf dist/SHA256SUMS.txt
```

В примере тег первой версии; для следующего обновления выбрать новый. Полная замена вложения того же релиза допускается при исправлении ошибочного файла, но tag и commit остаются согласованными с data/release.json. Обычное обновление исходников не требует нового релиза, пока пользователям не нужна новая готовая сборка.

Все сообщения коммитов пишутся на английском в формате Conventional Commits: type(scope): short imperative description. Коммиты небольшие и разделяются по смыслу; изменения программы, сборщика и документации не объединяются без необходимости. Большие сгенерированные наборы данных сохраняются отдельным коммитом.

Статические оригиналы не пересобираются и не редактируются. Новые файлы добавляются вместе с происхождением и контрольной суммой. Обновлённый файл источника получает новую сумму и проходит повторную проверку.
